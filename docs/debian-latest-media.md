# NP545XLA 蓝牙与摄像头综合日用入口

2026-11-09，蓝牙与摄像头已合入默认 **Debian 13 - Latest (Samsung)**，普通重启自动进入并通过运行复测。真实合盖待机 40.092 秒、开盖唤醒后，两项功能与 Wi-Fi 同时运行通过。原 Latest 保留为 **Previous Latest - before Bluetooth + camera**。本次不修改充电策略。

## 构建与安装

复用蓝牙 Image `163b71d2e6ae7deb2e0500de71d2b4639f1da80c68edb81a3477d1551e64735b`，其中包含已验证的 GPIO170 控制权及 GPIO50 合盖修复。蓝牙 DTB 去掉新增的 GPIO166 摄像头供电节点后，与已验收的蓝牙树规范化比较完全相同。该节点与先前摄像头试验一致。摄像头服务只加载 UVC，不自动采集或保存画面。

```sh
bash src/build-latest-media-boot.sh VERIFIED_BT_BOOT_DIR VERIFIED_CAMERA_DTB NEW_BOOT_DIR
# 三星 USB Debian：安装脚本、read-grub-menu.py、
# debian-bluetooth-media-wakeup、debian-bluetooth-media.conf 放在同一目录：
sudo bash src/install-latest-media-boot.sh --trial NEW_BOOT_DIR
# 完成真机验收后，才使用同一个包进行默认切换：
sudo bash src/install-latest-media-boot.sh --promote NEW_BOOT_DIR
```

打包器核对已验收的 EFI、Image、蓝牙及摄像头 DTB，检查设备树唯一差异、GRUB 语法和 EFI 内嵌菜单回读。安装器核对机型、内核、USB 根 UUID、分区关系、现有菜单和内核摘要，先备份 EFI，最后发布新菜单，并重新只读挂载核验。

候选阶段只追加 `Latest candidate - Bluetooth + camera`；原 Latest 入口逐字节不变。新增 `np545_media_once` 单次标记，进入候选前清零。晋升包只修改普通默认选择及两个入口标题；原 Latest 的完整启动配置保留为 `Previous Latest - before Bluetooth + camera`，其他独立测试入口保留。

## 同时运行验证

正常重启进入候选，启动 ID `88b99ec2-b2f9-4b73-826c-bd406319d70b`，不是新增冷启动验收。蓝牙冷启动能力已在上一阶段验证，本轮检验合并后的同时启用和恢复。`np545.media=1`、蓝牙及摄像头参数均生效，`hci0`、`video0`、`video1` 同时出现，蓝牙、摄像头和 LightDM 服务活动。

摄像头以 GStreamer 采集 MJPEG 并逐帧解码为 1280×720，立即丢弃画面。稳定阶段 1800 帧 / 59.530 秒，30.22 fps，最大间隔 36.91 ms，序号跳变为零。开流时首帧至第二帧为 396.12 ms、缺一个序号，与此前独立试验一致。

同一采集窗口内完成两轮全新 HCI Inquiry，分别 25.64 和 25.62 秒，均有成功完成事件。分别发现 7、8 个地址，交集 6 个；两轮均包含原 Windows 已知标牌 `…2C:5F`。Wi-Fi 绑定 `wlp1s0` 下载，两轮均为 138612 字节，SHA-256 `ed56aac47e7911e65ee63aae8d67e29f20e023f840e49f8ed037043a33de138a`；RX/TX 增量分别为 209789/6748、207069/7359 字节。

满电 / 5 V 启动的已知情况本次再次出现，原 GPIO101 服务等待原口 12 V 超时退出。它在上一轮独立蓝牙试验已经出现，不能算成本次合并的新故障，也不能称本次充电监控启动通过。本轮不调整充电电流、电压或刷新策略。

配对、蓝牙音频、会议软件以及 FFmpeg 的 MJPEG 解析兼容性不属于本次已通过项目。


## 合盖阶段的中断定位

用户确认实际做了两次开合，第二次等足 30 秒，并观察到开盖自行亮屏。系统记录的 5 次挂起/返回不能等同为 5 次人工合盖。该轮在盖子仍关闭时多次返回，尚不能宣称持续待机通过；没有据此切换默认。

开盖后的再次并行验证通过：摄像头稳定阶段 1800 帧 / 59.525 秒，30.22 fps、最大间隔 36.89 ms、序号跳变为零；两轮蓝牙 inquiry 成功完成并发现周边设备，分别 5、4 个地址，交集 3 个。这次仅第一轮出现 QMR `…4D:73`，不能称同一标牌连续两轮再次通过。Wi-Fi 两轮下载仍为同一 138612 字节文件，RX/TX 分别增加 195866/8272、192892/13501 字节。

当前内核未编译 PM_DEBUG、FTRACE、KPROBES，且未提供 /proc/kcore。使用按当前内核构建的临时只读观察模块，通过实时符号地址和 copy_from_kernel_nofault 仅读取 wakeup_irq 两个整数及 pm_abort_suspend，不写这些状态。最近一次返回读到 IRQ 167、abort=1；IRQ 层级对应 GPIO46 → PDC50 → GIC562，即蓝牙串口专用 RX 唤醒中断。该观测只证明最近一次返回来源，未把它直接推广为所有历史周期的原因。

随后在同一次启动中，仅将 c8c000.serial 的 power/wakeup 从 enabled 改为 disabled，保留原值，进行物理对照。Linux 7.0 的 wakeirq.c 用 device_may_wakeup() 决定是否把该 IRQ 武装为系统唤醒；串口运行时唤醒配置仍保留。[系统挂起与中断说明](https://www.kernel.org/doc/html/next/power/suspend-and-interrupts.html)。


## 实际待机和恢复通过

用户再次确认保持合盖至少 30 秒后开盖，屏幕自行亮起。北京时间 17:06:26.539 挂起前、17:07:10.044 恢复后的两条同步样本相隔 43.505 秒，其中实际 s2idle 为 **40.092 秒**，清醒阶段约 3.413 秒。成功计数从 5 到 6，失败仍为 0；观察模块记录本次唤醒为 IRQ 171，即 GPIO50 → PDC52 → GIC564。盖子事件也从关变为开。这次具备实际睡眠时长和正确开盖中断证据，不是仅凭亮屏或成功计数判断。

恢复后再次同时运行摄像头、蓝牙和 Wi-Fi：摄像头稳定阶段 1800 帧 / 59.498 秒，30.24 fps、最大间隔 36.86 ms、序号跳变为零；开流间隔 395.79 ms、最初缺一个序号。两轮全新 inquiry 均成功，分别为 25.60、25.62 秒，均发现 5 个地址，包含同一已知 QMR `…4D:73`。两轮 Wi-Fi 文件仍为相同 138612 字节及既有摘要，RX/TX 增量分别为 177016/13798、178308/11880 字节。

最终通过 [启动后配置](../src/debian-bluetooth-media-wakeup) 和 [服务追加配置](../src/debian-bluetooth-media.conf) 自动设置这一开关，只在 `np545.media=1`、正确三星板型及 c8c000.serial 原驱动匹配时执行。其他独立入口不改变该设置。**此版本暂不提供蓝牙设备唤醒整机能力；开盖唤醒已实测，蓝牙运行时 RX 唤醒配置保留。** 临时观察模块已卸载，两个临时合盖记录单元已结束，没有加入持久启动。

## 默认启动与回退

写入默认 EFI 后重新只读挂载实际 USB，核对菜单、DTB 和备份，再在九个单次标记均为 0 的状态下正常重启。实际进入综合版本，启动 ID 为 `2cd6313c-bf94-465f-92e8-ccbd67327ab3`。这是普通默认启动，未冒充另一次断电冷启动。启动日志确认 GPIO46 配置自动生效；hci0、video0/video1 和 LightDM 正常，临时观察模块不在内核中。

默认启动中的运行复测：摄像头 1800 帧 / 59.213 秒，30.38 fps、最大间隔 36.96 ms、序号跳变为零。两轮新 inquiry 分别 25.61、25.63 秒、发现 3 和 4 个地址，有 3 个共同地址；这一轮没有收到 QMR，未将它记成再次发现指定标牌。现场远处标牌的可发现性边界与前轮相同。两轮 Wi-Fi 仍下载到相同文件，RX/TX 增量为 229486/7236、224732/6983 字节。

回退时在 GRUB 选择 **Debian 13 - Previous Latest - before Bluetooth + camera (Samsung)**。该入口的完整启动体和原内核摘要 `509f2ff696f9dfc090e58bbe3a38593d8184561f6099fd328188243eb190561f` 保持不变；原独立蓝牙、摄像头等测试入口也保留。实际 EFI 分区另有原菜单备份 `EFI/BOOT/BOOTAA64.EFI.pre-media-30b61d900d8c1496` 和候选菜单备份 `.pre-media-8159c2f06f004d10`，最终均已读回核验。

最后一次启动仍遇到满电 / 5 V 的原有充电监控限制。核对原充电器能力、满电请求为零、BQ 目标 0 mA / 8400 mV、输入有效后，使用既有 Sink.select() 恢复 12 V / 3 A，再启动原 GPIO101 监控。前后 BQ 目标均保持 0 mA / 8400 mV，没有写 BQ 充电目标。最终为 12 V / 3 A、满电、电池电流 0、充电目标 0，GPIO101 服务为 active 并处于 idle-wait。充电源码摘要前后相同；此恢复是本次运行操作，没有宣称修复后续满电 / 5 V 启动兼容问题。

候选启动的内核日志曾出现一条 UVC `Failed to resubmit video URB (-1)`；该轮采集统计及后续多次重开均通过，未将整段内核日志描述为零警告。最终默认启动的归档中没有同类 UVC 或蓝牙超时/失败消息。
